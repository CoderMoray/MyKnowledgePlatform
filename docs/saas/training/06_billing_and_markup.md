# 06 · 计费与 markup（怎么收钱）

> 本文讲清"token plan 怎么计费、厂商个人套餐为什么不能转售、抽成多少、能否实时按真实费用算"。前提：已读 `01`–`05`、尤其 `03`（网关）。

---

## 6.1 两种"套餐"：Coding Plan vs Token Plan

| 维度 | 厂商个人 Coding Plan（¥469 等） | 你的 Token Plan（按量 API） |
|---|---|---|
| 认证 | 订阅 Key（个人开发者） | API Key（按量） |
| TOS | **禁多用户共享/商用**（阿里云明文；MiniMax 对多用户共享限速） | 开放平台按量，**允许商用/多租户** |
| 计量 | lump sum（如 71 亿 token/月 + 5h 滚动窗口） | 按 Key 精确计量，超预算拦截 |
| 多租户 | 共享一个池，谁冲猛谁打满窗口 | 每用户独立虚拟 Key，隔离 |
| 成本风险 | 月度过期作废（用不完/超额都亏） | 用多少付多少，零库存风险 |

**结论**：你对接国内厂商的**开放平台按量 API**，用 LiteLLM 给每用户发虚拟 Key 精确计量。**厂商个人套餐只该你自己用，别转售给用户。**

## 6.2 资金流（澄清一个常见误解）

```
用户付钱 ──► 你的 SaaS 钱包（用户看不到）
                    │
你统一持有少数几个 Provider 中央账户（DeepSeek/智谱/通义）──► 按量扣厂商
                    │
给每用户发一把"虚拟 Key"（预算上限 + 计量标签）──► 指向你的中央账户
```

- **不是"每用户 × 每模型开 plan"**：你只持有几个中央账户；用户只持虚拟 Key，跨所有允许模型、预算共享。
- **充值/开通全程服务端**：客户端只持虚拟 Key 字符串（harness 写入 `opencode.json`），用户无感、碰不到 Provider 账户。

## 6.3 抽成（markup）一般多少

行业 API 转售/聚合通常加价 **10%–50%**。落地建议：

| 模型档 | 建议 markup | 理由 |
|---|---|---|
| 经济型（DeepSeek/通义/智谱） | **2x–3x** | 绝对值极小（¥0.004/次问答），用户无感、你毛利高 |
| 标准/高级 | **1.3x–1.8x** | 保持竞争力 |
| 套餐打包 | 毛利率 **30%–60%** | 靠"大多数人用不满"盈利 |

**真实数字感**：DeepSeek V4-Flash 输入 ¥1/M、输出 ¥2/M。一次知识库问答 ≈ 3K 上下文 + 500 输出 ≈ ¥0.004。收 2x = ¥0.008/次，用户 1500 次/月才 **¥12**——对他忽略不计，对你几乎纯毛利。

## 6.4 能否按 API 真实费用实时计算？——能，且推荐

```
用户请求(带虚拟Key) → 网关鉴权+查预算 → 调厂商
                                   ↓ 完成
        LiteLLM 按 pricing map 算本次真实花费 → 写 SpendLogs(按Key)
                                   ↓
        后端读该 Key 的 spend(/spend/get 或 webhook)
                                   ↓
        钱包扣款 = 真实花费 × markup
                                   ↓
        预算耗尽 → LiteLLM 返 429 硬停（绝不爆账单）
```

两点说明：
- **Token 数准确**（取自厂商返回的 `usage`）；**单价**是 LiteLLM 社区 `pricing.json` 近似值，可能滞后或漏缓存折扣——每月用厂商真实账单对账一次，留 10–20% buffer，可自定义覆盖单价。
- 纯国内低价模型计费结构简单，LiteLLM 表基本准，对账压力小。

## 6.5 BYOK：让你零垫付

用户在自己填的 DeepSeek/智谱 Key 下消耗，你**只收 SaaS 订阅费**，连中央账户的钱都不用垫。作为付费选项之一，降低你的资金压力。
